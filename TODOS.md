## P0: Security & Correctness

### 1. ~~Migrate all `process.env` to `ConfigService` (11+ files)~~ ✅ Done (2026-06-12)

**What:** Replace direct `process.env` access with NestJS `ConfigService` injection in 11 production files.
**Why:** `auth/constants.ts` loads `JWT_SECRET` at module parse time, before `env.validation.ts` runs. If the env var is missing, JWT signs with an empty string — silently broken auth. Other files bypass the validated config, making them untestable without `process.env` manipulation.
**Resolution:** `auth/constants.ts` was removed and most files migrated in earlier PRs. Remaining: `prisma/prisma.service.ts` now injects `ConfigService`. `live.gateway.ts` and `licenses.controller.ts` read env in decorators (evaluated before DI is available) — access centralized in documented helpers `config/cors.config.ts` and `utils/upload-storage.util.ts`. Config factories (`config/ffd.config.ts`) legitimately read `process.env` per NestJS convention.

## P1: Convention Compliance

### 2. Add `take` limits to all unbounded `findMany()` queries (7+ queries)

**What:** Add `take` + pagination to all unbounded Prisma `findMany()` calls.
**Why:** CLAUDE.md convention. A club with 200+ members or a user with 100+ career results will generate heavy payloads. Risk of slow responses and memory pressure.
**Files:** `partnership-query.service.ts` (3 queries), `career-query.service.ts` (4 queries), `competition-results.service.ts` (2 queries), `solo-team.service.ts` (1 query), `notifications.service.ts` (1 query)
**Effort:** human ~1.5h / CC ~15min
**Depends on:** Nothing

### 3. Replace `include` with `select` in registration and auth flows

**What:** Replace `include: { competition: true }` with targeted `select` in `competition-registration.service.ts` (4 spots). Replace `include: { user: true }` with `select: { userId: true }` in `auth-password.service.ts` (1 spot).
**Why:** `include: { competition: true }` loads the `layout` JSON field (seat map, potentially large) unnecessarily. `include: { user: true }` loads the password hash into memory for no reason.
**Files:** `competition-registration.service.ts`, `auth-password.service.ts`
**Effort:** human ~30min / CC ~10min
**Depends on:** Nothing
